## 2. Аудио-движок

### 2.1. Принцип
Не воспроизведение файлов, а **процедурный синтез** по графу. Параметры графа модулируются дыханием в реальном времени. Каждая сессия уникальна (семя генерируется из `user_id + timestamp`).

### 2.2. Граф (слои)

| Слой | Что это | Роль |
|---|---|---|
| **Sub** | 2 синуса 40–60 Гц, слегка расстроенные | «телесный» бас, ощущается на динамике |
| **Drone** | 3–4 пилообразных/треугольных, ФНЧ 200–900 Гц | гармоническая основа, «дыхание» фильтра |
| **Pad** | аккорд (минорная пентатоника, 4 голоса), медленные fade | эмоциональная окраска |
| **Air** | шум через полосовой фильтр | «воздух», связывается с амплитудой вдоха |
| **Pulse** | мягкий синус на частоте дыхания (0,08–0,12 Гц, субгармоники) | тактильность |
| **Bell** | колокол на завершении выдоха (опционально, «награда») | маркер цикла |
| **Voice** | TTS-фраза (если включено) | ведение |

Обработка: `sum → EQ (low-shelf +2 dB @80 Hz, -1.5 dB @3 kHz) → Compressor (мягкий, 2:1) → Convolver (IR 2.4 с, сгенерирован) → Limiter (-1 dBTP) → out`.
Защита слуха: мастер-громкость по умолчанию 60%, максимум −6 dBFS RMS, лимитер всегда включён.

### 2.3. Мэппинг «дыхание → звук»

```
env(t)        — текущая огибающая дыхания, 0..1 (сглаженная)
phase(t)      — inhale | exhale | pause
rate(t)       — текущая частота, вдохов/мин

drone.cutoff   = 220 + 680 * env
sub.gain       = 0.08 + 0.14 * env
air.gain       = 0.02 + 0.10 * max(0, d(env)/dt)      // «вдох» = шумовая волна
air.centerFreq = 350 + 900 * env
pad.gain       = lead ? 0.10 : 0.16                    // в ведении — тише, чтобы не отвлекать
reverb.wet     = 0.22 + 0.18 * (1 - env)
stereo.width   = 0.6 + 0.4 * env
```
Переходы — `setTargetAtTime` с τ = 0,08–0,25 с, чтобы не было «щелчков» и чтобы отклик ощущался мгновенным.

### 2.4. Ведение (энтрейнмент)
- `targetRate` уменьшается ступенями по 0,3–0,5 вдоха/мин каждые 30 с до достижения персонального резонанса.
- Визуальный и звуковой такт **не расходятся**: единый clock, звук = slave, визуал = slave.
- Если `rate(user)` > `target + 1,5` больше 15 с → движок останавливает спуск и возвращается в зеркало (никакой ошибки).
- Задержка «предсказания»: фаза предсказывается на 250 мс вперёд (линейная экстраполяция огибающей), чтобы компенсировать латентность микрофона.

### 2.5. Требования
- 48 кГц, стерео, float; буфер 256–512 сэмплов (≈5–11 мс) для отклика.
- Расход CPU < 8% на среднем устройстве (iPhone 11 / Pixel 5).
- Расход батареи ≤3% за 10 мин.
- Работа в фоне (iOS `audio` background mode, Android foreground service).
- Детерминированный seed → воспроизводимость для QA.


### 2.6. Слои среды (layered ambience)

Среда — это не трек, а **стек независимых текстур**, каждая из которых ведёт себя как отдельный «инструмент» в микшере и модулируется дыханием.

**Два способа реализации (выбор по устройству):**

| Способ | Плюсы | Минусы | Где применяем |
|---|---|---|---|
| A. Процедурный реальный синтез (гранулярные/шумовые узлы, огибающие, рандомные события) | 0 памяти, бесконечная вариативность, нет стыка петли | выше CPU, сложнее «птичьи фразы» | приоритет на мобильных |
| B. Офлайн-рендер буфера 8–12 с + бесшовная петля | дёшево по CPU, предсказуемо | память, риск слышимого цикла | веб-демо, слабые устройства |

**Правила для способа B (как в прототипе):**
1. Буфер рендерится генератором в 2 канала, 12 с, 48 кГц.
2. **Нормализация по целевой RMS** (0,10–0,19 в зависимости от плотности текстуры) с жёстким ограничением пика 0,9 — иначе редкие события (птицы, капли) звучат громче плотного шума.
3. **Бесшовная петля:** последние 350 мс микшируются с первыми 350 мс (equal-power кроссфейд). Без этого на стыке слышен щелчок.
4. Кэш по ключу `layer@sampleRate`; повторные включения не пересчитывают буфер.
5. Память: ≤12 МБ на все среды; слои с нулевой громкостью дольше 30 с выгружаются (source.stop + освобождение буфера).
6. Тяжёлые буферы рендерятся после отрисовки кадра (кнопка показывает «готовим среду»), чтобы UI не замирал.

**Модель смешивания:**

```
layerGain_i = pow(vol_i, 1.25)            // перцептивная кривая
ambientBus  = (0.82 + 0.18 * env) * (1 - 0.88 * space)
masterOut   = 0.18 + 0.60 * userVolume
```
- Все слои идут в общий `ambientBus` → `dry` + 30% в реверб.
- Порядок: `sum(slaves) → ambientBus → [dry | reverb] → master → limiter(-1 dBTP)`.
- Изменение громкости слоя — `setTargetAtTime(τ=0,25 с)`, включение — fade-in 250 мс, выключение — fade-out 250 мс и только потом `stop()`.
- В фазе «Пространство» шина уходит на −88% вместе с генеративной основой: среда тоже замолкает.

**Каталог v1:** море, ручей, дождь, птицы, ветер, сверчки, костёр, гроза, поезд, кафе. Расширение — контент-паки (см. бизнес-план), но каждый пак — это **новые текстуры того же движка**, а не отдельные треки.

### 2.6a. Мастер-громкость, пауза и прерывания

**Цепочка (важно для порядка узлов):**
```
slaves → [dry | reverb] → master(Gain) → hpFilter(динамик) → panner → limiter → out
```
- `masterTarget = muted ? 0.0001 : 0.18 + 0.60 × volume` (максимум 0,78).
- Изменения — `setTargetAtTime(τ = 0,08 с)`; mute не обнуляет сохранённый уровень.
- «Тихий старт»: 35% цели за 2,5 с → 100% к 18 с (экспоненциальные рампы).
- Пауза: `master → 0,0001` за 0,25 с; снятие — 0,6 с; узлы не останавливаются, поэтому нет щелчков и пересоздания графа.
- `ctx.onstatechange`: если ОС приостановила контекст (`suspended`) во время активной сессии — автоматическая пауза + предложение продолжить. Не теряем сессию при звонке.
- Режим динамика: highpass 130 Гц + бас ×0,55 (на телефоне низ только «бубнит», а не слышится).

**Тайминги и фон:**
- Сессия считается по `performance.now()`, а не по числу кадров, поэтому пауза реализуется сдвигом `startAt`.
- В скрытой вкладке `requestAnimationFrame` не тикает: планировщик переключается на `setInterval(250 мс)`, иначе сессия «замерзает» и никогда не завершается.
- `visibilitychange` перезапускает драйвер и повторно берёт Wake Lock (браузер снимает его при уходе в фон).

### 2.7. Свои звуки

- Вход: mp3/wav/ogg/m4a ≤12 МБ, ≤10 мин. Декодирование через штатный декодер (`AudioFile`/`MediaCodec`/`decodeAudioData`).
- Обработка: нормализация по RMS к 0,15, ограничение пика 0,9, кроссфейд петли 350 мс; файлы короче 1,5 с — предупреждение о заметном цикле.
- Хранение: **только локально** (IndexedDB на вебе, файловая система приложения на мобильных, с шифрованием на уровне ОС). На сервер не передаётся никогда — это защищает и приватность, и авторские права.
- Квота: 12 своих слоёв, общий объём ≤150 МБ; при превышении — предложение удалить старые.
- Удаление: файл + метаданные + запись в микшере, в один тап.
- Юридически: пользователь подтверждает, что имеет права на файл; продукт не распространяет его и не включает в каталог.

## 3. Детекция дыхания (без носимых устройств)

### 3.1. Пайплайн (всё на устройстве)

```
mic(16 kHz, mono)
 → highpass 80 Hz
 → noise gate (адаптивный, по перцентилю 20 шума)
 → RMS-огибающая (окно 30 мс, хоп 10 мс)
 → EMA-сглаживание (α = 0.25)
 → оценка шума и SNR
 → детектор экстремумов (гистерезис, адаптивные пороги от шума)
 → классификатор фазы (нарастание = вдох, спад = выдох, плато = пауза)
 → фильтр Калмана по периоду (сглаживание rate)
 → {env, phase, rate, quality}
```

### 3.2. Ключевые правила
- Порог: `thr_hi = noise + 0.35*(peak - noise)`, `thr_lo = noise + 0.15*(peak - noise)` (гистерезис).
- **Пороги фаз — адаптивные, от локальных min/max огибающей** (`hi = min + 0.62*(max-min)`, `lo = min + 0.28*(max-min)`), где min/max медленно следуют за сигналом (быстро вниз/вверх, медленно обратно). Причина: фиксированные пороги не работают на поверхностном дыхании — огибающая не опускается ниже порога, вдохи перестают детектироваться и частота вообще не считается. Это проверено в прототипе: до правки за 120 с обнаруживался один вдох, после — стабильные ≈6/мин.
- Плоское дыхание (динамика < 0,12) даёт низкий `quality` → режим «ведём вас», без сообщений пользователю.
- Два вдоха ближе 1,2 с — второй игнорируется (физиологический предел).
- Пики ближе 1,2 с друг к другу игнорируются (физиологический предел ≈ 50 вдохов/мин).
- Валидный цикл: 3,5–15 с (4–17 вдохов/мин); вне диапазона — цикл не учитывается.
- `quality` = взвешенная комбинация SNR, стабильности периода и доли валидных циклов (0..1).
- При `SNR < 8 дБ` 6 секунд подряд → `mode = guided` (ведём по таймеру), без сообщений пользователю.
- Разговор/музыка рядом: детектор речи (простой VAD по спектральному потоку) → игнорировать.

### 3.3. Валидация
- Эталон: поясной пьезо-датчик (или камера) на 30 испытуемых, 3 условия (тишина / офис / улица).
- Метрики: MAE частоты ≤1,0 вдоха/мин; accuracy фаз ≥85%; латентность p95 <300 мс; ложные срабатывания <5%.
- Регресс-набор: 200 записей дыхания в репозитории (с согласием), прогоняется в CI.

### 3.4. Приватность по конструкции
- Аудио-буфер живёт только в RAM, не пишется на диск, не отправляется.
- Нет записи/распознавания речи: только энергия и спектр, речь отбрасывается.
- Индикатор записи ОС всегда виден; приложение показывает свой индикатор.
- Kill-switch в настройках, доступен с локскрина (для iOS — через настройки приватности).

## 4. Машина состояний сессии

```
IDLE → PREFLIGHT → MIRROR → [RF_SCAN] → LEAD → SPACE → RESULT → IDLE
                    │           │         │       │
                    └───────────┴─────────┴───────┴→ ABORTED (partial)
                                   └→ GUIDED_FALLBACK (нет сигнала)
```
- `PREFLIGHT`: проверка аудио-маршрута, громкости, разрешений.
- `MIRROR`: 60–120 с.
- `RF_SCAN`: включается, если сессия помечена как калибровочная (первые 3–5).
- `LEAD`: основная длительность.
- `SPACE`: последние 20% (≤60 с).
- `RESULT`: экран с одним тапом.
Любой переход — плавный (fade 1,5–3 с), без пауз и «загрузок».

## 5. «Отпечаток»: модель персонализации

### 5.1. Признаки (на сессию)
`duration, time_of_day, weekday, lead_start_rate, lead_end_rate, target_rate, rf_estimate, timbre, bass_gain, mode(mirror/lead/guided), voice_on, music_seed_family, quality, completion_ratio, minutes_to_calm, outcome(3), streak_of_same_preset, device(phone_held/table), ambient_noise`.

### 5.2. Задача
Предсказать `minutes_to_calm` и `outcome` для набора параметров → выбрать лучший набор для следующей сессии.

**Модель (v1):** градиентный бустинг (CatBoost/LightGBM) на сервере, обучение раз в сутки по всей базе + персональные веса.
**Холодный старт:** правила + когортные приоры (по времени суток, по заявленной цели, по «мягкому режиму»).
**Персонализация:** байесовское смешивание личной и общей модели (иерархический приор: `w_personal = n/(n+k)`, `k ≈ 8`).
**Онлайн:** клиент делает выбор пресета локально по «отпечатку» (веса ≤ 20 КБ), сервер дообучает глобальную модель.

### 5.3. Выход
`preset = {mode, duration, target_rate, timbre, bass, voice_id, seed_family}` + объяснение одной строкой («вы лучше засыпаете с низким басом после 22:00»).

### 5.4. Валидация модели
- Офлайн: MAE по «минутам до покоя» ≤ 45 с на holdout.
- Онлайн: A/B (модель vs фиксированный пресет), 4 недели, primary — медиана «минут до покоя».
- Обязательный контроль: не оптимизировать «время в приложении» (это анти-метрика).

## 6. «Общая волна»: протокол синхронизации

Сервер не передаёт аудио. Только фазу.

```
// сервер
room = {
  id, epochStartMs, periodMs (6000..13000), mode,
  participants (rolling), avgRate, phase
}
broadcast (1 Гц):
  { t: serverTimeMs, epoch: epochStartMs, period: periodMs, n: participants }
```

Клиент:
```
localPhase = ((now + clockOffset) - epoch) mod period / period
clockOffset = медиана(serverTime - clientTime) по последним 5 тикам  // NTP-подобная оценка
smoothOffset (экспоненциальный фильтр, τ=20 c)                        // без рывков
```
- При потере связи клиент продолжает по локальным часам (интерполяция дрейфа), без остановки.
- Точность: p95 |offset| < 150 мс; коррекция — только сдвигом фазы ≤5% периода (неслышимо).
- Трафик: ~40 байт/сек на клиента. 100 000 участников ≈ 4 МБ/сек на выходе (кластер WS, шардирование по комнатам).
- Участники: только счётчик + гистограмма отклонений (анонимная, агрегированная), без идентификаторов.

## 7. API (контракт, v1)

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/v1/auth/anon` | анонимный профиль, device-attestation (App Attest / Play Integrity) |
| POST | `/v1/auth/link` | привязка к Apple/Google (опционально) |
| GET | `/v1/preset/next` | рекомендованный пресет (или локальный фолбэк) |
| POST | `/v1/session` | старт сессии → `session_id` |
| POST | `/v1/session/{id}/finish` | телеметрия сессии (см. схему), без аудио |
| PUT | `/v1/session/{id}/outcome` | `better/same/worse` + опц. шкалы |
| GET | `/v1/fingerprint` | формула, графики, топ-факторы |
| DELETE | `/v1/fingerprint` | сброс модели |
| POST | `/v1/voice/clone` | старт клонирования (upload → consent → job) |
| POST | `/v1/voice/{id}/consent` | фраза-подтверждение (liveness) |
| DELETE | `/v1/voice/{id}` | отзыв, удаление ≤24 ч |
| GET | `/v1/live/rooms` | список комнат и расписаний |
| WS | `/v1/live/{room}` | фазовые тики |
| GET | `/v1/b2b/stats` | агрегаты (≥10 чел. в срезе) |
| POST | `/v1/subscription/sync` | RevenueCat webhook |

Ошибки: единый формат `{code, message, retryable}`; клиент никогда не блокируется ошибкой сервера (всё критичное — офлайн).

## 8. Схема данных (основное)

```sql
user(id, created_at, locale, tz, anon, org_id, flags jsonb)          -- без email по умолчанию
session(id, user_id, started_at, ended_at, mode, planned_sec, actual_sec,
        status, preset jsonb, rf_bpm, quality, minutes_to_calm,
        outcome, outcome_scales jsonb, device jsonb)                  -- без аудио!
fingerprint(user_id, rf_bpm, weights jsonb, updated_at, n_sessions)
live_room(id, schedule_cron, period_ms, mode, active)
voice_model(id, user_id, kind(self|other), consent_video_ref, status,
            created_at, revoked_at)                                   -- аудио в S3, шифр., TTL
org(id, name, plan, seats, domain)
org_member(org_id, user_id, role)                                    -- агрегаты только
subscription(user_id, plan, status, provider, renews_at)
event(id, user_id, name, props jsonb, ts)                            -- партиционирование по дате
```

**Запрещено хранить:** аудио пользователя, транскрипты, биометрию (пульс/HRV), геолокацию, содержимое календаря. Всё, что нужно для продукта, — числа.

## 9. Безопасность, приватность, комплаенс

| Требование | Реализация |
|---|---|
| 152-ФЗ (РФ) | данные граждан РФ — на серверах в РФ; отдельный кластер, отдельные ключи |
| GDPR / CCPA | DPA, право на удаление/экспорт в 2 тапа, минимизация |
| Медицинские заявления | продукт — «wellness», не медизделие; дисклеймер в онбординге, настройках, сторах |
| Клонирование голоса | согласие + liveness-фраза + запрет свободного текста + отзыв + C2PA-метка |
| Дети | 16+ на старте; 13+ только с подростковым профилем и согласием (v2) |
| Кризисные состояния | постоянная ссылка «Помощь» с региональными контактами; триггер после 3× «хуже» |
| Атаки | App Attest / Play Integrity, rate-limit, подпись запросов, WAF |
| Аудио в сеть | технически невозможно: нет кода отправки аудио; проверяется в CI (статический анализ запрещает `mic → network`) |

**Юридическая рамка продукта:** «инструмент саморегуляции и релаксации». Формулировки в сторах — без слов «лечит», «терапия», «тревожное расстройство».

## 12. Тестирование

1. **Юнит:** DSP-функции, машина состояний, мэппинг параметров, выбор пресета.
2. **Аудио-регресс:** рендер 30 пресетов → спектральные «снапшоты» + LUFS-контроль (не тише −38 LUFS, не громче −16 LUFS).
2a. **Тест сред:** каждый генератор — на NaN/денормалы/пик; проверка бесшовности петли (разница первых и последних 350 мс после кроссфейда); проверка пика суммы 8 слоёв на лимитере; тест «среда не играет после ухода с экрана».
3. **Детекция дыхания:** 200 эталонных записей, матрица условий (шум 35/45/55 дБ, телефон в руке/на столе/в кармане, маска, дыхание ртом/носом).
4. **E2E:** Detox/Maestro — онбординг, сессия, пейволл, отмена подписки, удаление данных.
5. **Полевой тест:** 30 человек × 2 недели, дневник + HRV-браслет (только для валидации, не в продукте).
6. **Нагрузочное:** live-комната 10 000 WS, 100 000 WS (шардирование).
7. **Приватность:** сетевой сниффер в CI на «утечку» аудио; тест удаления данных.

**План валидации эффективности (для white paper):** рандомизированное сравнение «Отклик» vs «пассивное аудио» vs «ожидание», 4 недели, n=120, первичные исходы — PSS-10, STAI-S, ISI (сон), вторичные — HRV (опционально, браслет). Публикация результатов — доверие, B2B-продажи, PR.

## 14. Технические риски

| Риск | Вероятность | Митигация |
|---|---|---|
| Детекция дыхания нестабильна в шуме | Средняя | Фолбэк в «ведём вас», вибро-режим, инструкция «дышите ближе к телефону» |
| Микрофон пугает пользователей | Высокая | Приватность как маркетинг, индикаторы, отказ = рабочий продукт |
| Клонирование голоса → скандал | Средняя | Жёсткий консент-флоу, запрет свободного текста, C2PA, отзыв, юр. заключение |
| Генеративный звук «плоский» | Средняя | Гибрид: процедурная основа + лицензированные сэмплы-слои (не музыка, а текстуры) |
| Лицензии на аудио-текстуры | Низкая | Собственный синтез, публичные CC0-библиотеки, юр. аудит |
| Регуляторные претензии по «медицине» | Средняя | Язык, дисклеймеры, отсутствие диагностики, юрист на ревью текстов |
